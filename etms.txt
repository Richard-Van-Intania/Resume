LINKEDIN / PORTFOLIO DESCRIPTION
I contributed a focused post-production enhancement to an existing ETMS e-Seal Android application. My scope was to add a QR-based lookup that allows an operator to scan an e-Seal device and view how many usage cycles have been recorded for it.

I extended the application’s existing QR scanner to distinguish seal/device identifiers from QR values already used by the login flow. The updated parser supports QR payloads containing an `IMEI:` prefix as well as 12-character numeric and alphanumeric device codes. Device codes can be scanned from the live camera or extracted from an image selected from the gallery.

When a supported identifier is detected, the app routes the user to a new seal-details screen and passes the normalized device code through Navigation Compose. A ViewModel calls the e-Seal usage endpoint with the required authorization header, decodes the response, and exposes the total usage count through StateFlow. The Jetpack Compose interface displays the seal number and handles loading, unsuccessful HTTP responses, connection failures, and successful results.

This was an enhancement to an application that was already in production, rather than development of the entire ETMS system. I integrated the feature with the established architecture and existing QR behavior, then prepared the Android configuration and release updates needed for the enhanced version.

INTERVIEW SUMMARY
The ETMS application was already in production when I joined this work. My responsibility was limited to adding a new QR-based usage-cycle lookup, so I first studied the existing scanner and navigation behavior to avoid breaking the QR login flow.

The scanner originally treated scanned data as login-related content. I extended its parsing logic to recognize e-Seal device identifiers in several real-world formats: an `IMEI:` payload, a 12-digit code, or a 12-character alphanumeric code. The same rules are applied to both live CameraX frames and QR images selected from the gallery. Valid alphanumeric values are normalized to uppercase before lookup.

When the scanner recognizes a device code, it navigates to a new details destination instead of following the login path. The destination receives the code as a route argument, and its ViewModel makes an authorized request to the e-Seal usage endpoint. I used StateFlow to expose the current state to the Compose UI and Kotlin Serialization to safely decode the `total_usage_count` response.

The key engineering consideration was backward compatibility: the new device-code workflow had to coexist with the existing QR authentication behavior. I therefore added targeted content detection and conditional routing rather than replacing the scanner’s original logic.
