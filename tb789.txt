PORTFOLIO / LINKEDIN DESCRIPTION
TB789 is an independent side project that I originally created under the name 789plates. The idea is to build a specialized marketplace and discovery platform for Thai vehicle registration plates, where collectors, buyers, and sellers can find meaningful number patterns, browse plate categories, manage listings, and follow stores.

Unlike a generic classified marketplace, TB789 models the structure of Thai registration plates directly. A listing can include a numeric prefix, Thai character group, trailing number, plate style, province, vehicle category, special prefix, price, quantity, seller, and optional listing image. The client renders recognizable plate previews using the correct visual style and custom Thai plate typography.

The search system interprets user input according to common plate structures: number-text-number, number-text, text-number, text-only, or number-only. It sends a normalized search model to specialized backend queries and separates exact results from suggestions. Users can refine results by plate type, province, vehicle class, maximum price, availability, sort order, and presentation style.

Seller functionality includes creating listings, selecting the supported Thai province and plate category, entering plate characters and numbers, uploading/cropping imagery, setting price and inventory quantity, adding information, and pinning important listings. Marketplace users can view plate and store details, like or save plates and stores, inspect seller inventory, and see reaction and collection counts.

I built the backend in Rust with Axum and Tokio. PostgreSQL persistence is implemented with SQLx, while authentication uses access and refresh JWTs. Registration and password-recovery flows issue expiring email verification codes through an SMTP mailer. Protected routes pass through API-key, email-validation, uniqueness, and bearer-token middleware. Listing/profile media uses AWS S3 presigned operations and CloudFront URLs.

The Flutter application uses Riverpod for generated asynchronous state, Freezed and json_serializable for typed models, GoRouter for nested application navigation, and secure storage for credentials. It supports Thai and English, light and dark themes, cached remote images, responsive layouts, and native camera/gallery image selection.

The project began as several 789plates prototypes and was later renamed and reorganized as TB789. It remains an actively developed side-project prototype. Authentication, listings, profiles, search, seller queries, filters, likes/saves, and core infrastructure are implemented; real-time chat and plate-transfer modules are still under development.

INTERVIEW SUMMARY
I created TB789 independently from product idea through mobile UI, domain modeling, backend APIs, database queries, authentication, and media infrastructure. It began as 789plates and was renamed TB789 as the product structure and visual identity evolved.

The most interesting technical problem was search. Thai plates are not a single free-text field; they combine optional leading numbers, Thai characters, trailing numbers, province, vehicle class, and multiple visual categories. I created parsing rules that classify the user’s query, validate allowed Thai characters and numeric positions, and select an appropriate backend query. The API returns exact results and suggestions so the app can still surface relevant inventory when there is no perfect match.

On the backend, I chose Rust, Axum, Tokio, and SQLx to build a typed asynchronous service. PostgreSQL queries combine listing, seller, reaction, saved-state, and pagination information. Middleware validates API keys, email formats, email uniqueness, and JWT bearer tokens before protected handlers execute.

I also implemented the complete account lifecycle. New users request a verification email, enter an expiring reference/code pair, create an account, and receive access and refresh tokens. The Flutter app stores tokens securely and renews sessions automatically. Similar verified flows support forgotten passwords, while authenticated endpoints handle password changes and account deletion.

Because this is an active side project, I distinguish working infrastructure from planned features. The marketplace, account, listing, search, filtering, profile, and collection foundations are implemented. Chat and plate-transfer screens are architectural placeholders or early prototypes and are not presented as completed production features.
