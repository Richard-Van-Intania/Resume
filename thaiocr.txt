PORTFOLIO / LINKEDIN DESCRIPTION
Thai OCR WebAssembly Demo is a browser-based document-analysis application that I designed and developed independently to demonstrate FINEMA’s OCR and identity-document services. The frontend is built with Flutter and compiled to WebAssembly, allowing users to access the tools directly through a modern web browser.

The application provides four focused workflows:

1. General Document OCR — uploads a document, shows each processed page beside the extracted text, and lets users copy the recognized content to the clipboard.
2. Passport Analysis — extracts MRZ information and presents structured passport fields, formatted dates, the processed page image, and the service’s MRZ validation status.
3. Thai National ID Analysis — extracts structured Thai and English identity information, dates, religion, address data, face imagery, and the analyzed card image.
4. Card Liveness Detection — analyzes whether the submitted image represents a physical identity card and presents the processed image with a clear pass/fail result.

Users can upload JPG, JPEG, PNG, or PDF files of up to 5 MB. The browser keeps file bytes in memory, validates the selected files, and sends Base64-encoded content to the appropriate REST service. Each tool has its own file state and result flow, with loading indicators, deletion controls, and error handling.

I implemented the complete application: responsive Material 3 UI, login and persistent demo sessions, nested tool navigation, Riverpod state management, generated API providers, Freezed response models, REST integration, image decoding, structured result views, Flutter WASM compilation, Firebase configuration, SPA routing, and Firebase Hosting deployment.

The WebAssembly component is the browser frontend and presentation layer; OCR and liveness inference are performed by FINEMA’s backend document-analysis APIs.

INTERVIEW SUMMARY
I built the Thai OCR WebAssembly Demo independently as a browser-based interface for several FINEMA machine-learning services. The main design challenge was presenting very different response shapes—free-form page text, passport MRZ data, detailed Thai ID fields, and a binary liveness result—inside one consistent application.

I separated the application into four stateful tools. Each has its own file manager and API provider, which prevents a file or pending result from one workflow affecting another. Riverpod manages file lists and asynchronous requests, while Freezed and generated JSON serializers provide strongly typed response models.

For the browser upload flow, I used the web-compatible file picker to read bytes directly into memory. The selected document is validated by format and size, Base64-encoded, and sent to the correct REST endpoint. The returned JSON includes structured fields and Base64 images, which the UI decodes and displays alongside the extracted information.

The application was compiled with Flutter’s WebAssembly target and configured as a single-page app on Firebase Hosting. I also implemented the Firebase setup and deployment process. The OCR models themselves run behind FINEMA’s APIs; WebAssembly is used to deliver the Flutter client efficiently in the browser.
