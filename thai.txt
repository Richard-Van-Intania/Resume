PORTFOLIO / LINKEDIN DESCRIPTION
Thai.ID by FINEMA is a privacy-focused mobile utility that I developed independently to simplify the creation of certified identity-document copies. I first built the product as a cross-platform Flutter application for Android and iOS, then used the same product requirements and visual language to reengineer native implementations with SwiftUI and Jetpack Compose. I also created a smaller Android Views proof of concept to compare traditional Fragment/XML architecture with Compose.

The original Flutter application replaces the manual workflow of printing an identity document, writing certification text, signing it, crossing the copy, rescanning it, and sharing the result. Users can capture a document with the camera, select an image from the gallery, or import a PDF; arrange the content in card or A4 layouts; add Thai or English certification text and dates; draw or reuse a handwritten signature; hide unnecessary personal fields; and export the final copy as a PDF or image.

For Android, I rebuilt the main workflow using Kotlin and Jetpack Compose. The native implementation includes onboarding, app navigation, profile and localization features, passcode and biometric flows, layout selection, CameraX capture, PDF page selection with PdfRenderer, image cropping, document placeholders and previews, certification composition, signature drawing, and locally saved signatures and layouts. Room manages structured history data, while Proto DataStore persists settings, localization, and security preferences.

For iOS, I rebuilt the application shell and account/security experience in SwiftUI. It includes independent NavigationStack paths for home, history, and profile; onboarding and terms; bilingual localization through String Catalogs; profile display/editing; settings and support; BCrypt-protected six-digit passcodes; and Face ID/Touch ID through LocalAuthentication. AppStorage persists the current profile, authentication preferences, agreements, and display settings.

The Android Views proof of concept uses Kotlin, XML layouts, Fragments, View Binding, ViewPager, Safe Args, and Navigation Component to implement the loading, welcome, onboarding, and terms flow. It served as a direct comparison between traditional Android UI development and the declarative Compose rewrite.

This multi-implementation work demonstrates more than framework translation: I mapped the same product behavior into each platform’s native navigation, persistence, authentication, localization, media, and lifecycle patterns while preserving a consistent Thai.ID experience.

INTERVIEW SUMMARY
I originally developed Thai.ID by FINEMA independently in Flutter, including the document-processing workflow, editor, selective disclosure, e-signatures, export pipeline, local database, authentication, localization, and native mobile configuration. I later rebuilt key parts of the product in SwiftUI and Jetpack Compose instead of mechanically translating widgets.

The main lesson was that equivalent product behavior requires different native designs. In Flutter, Isar stores preferences, signatures, layouts, and export history. In Android Compose, I separated structured signature/layout records into Room and stored configuration in Proto DataStore exposed through Flow. In SwiftUI, I used AppStorage for the implemented profile, navigation, localization, and security state.

Authentication also required platform-specific approaches. The Flutter version hashes the six-digit PIN with a per-user salt and uses a cross-platform biometric plugin. The Android rewrite integrates BiometricPrompt, while the SwiftUI rewrite uses LocalAuthentication and BCrypt password verification.

For native Android media workflows, I implemented CameraX capture, content-URI handling, PdfRenderer-based page selection, bitmap conversion, cropping, and PNG/JPEG persistence. The SwiftUI work focuses on native lifecycle, NavigationStack routing, state persistence, localization, and account security. I also built a Fragment/XML version of the onboarding flow to compare imperative Android Views with declarative Compose.

This work gave me practical experience evolving one product across three UI paradigms—Flutter, SwiftUI, and Jetpack Compose—while understanding when to preserve product behavior and when to redesign architecture around platform conventions.
