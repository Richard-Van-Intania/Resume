PORTFOLIO / LINKEDIN DESCRIPTION
E-Passport is a cross-platform mobile prototype that I designed and developed independently for a bidding demonstration presented in the context of Thailand's Ministry of Foreign Affairs (กระทรวงการต่างประเทศ). Its purpose was to demonstrate a complete digital passport-service experience rather than represent a publicly deployed production system. It brings together identity-document capture, biometric verification, electronic passport reading, enrollment, payment, passport retrieval, consent, and verification in a single Flutter application.

The main applicant journey lets a user register with a Thai national ID card or an existing passport, extract and review identity information, attach supporting documents, complete facial liveness and eye checks, compare a live face against document imagery, capture and assess a compliant passport portrait, run ABIS verification, select passport options, choose a payment method, preview an invoice, and submit the application. The application also includes separate experiences for retrieving a completed passport, proving ownership through NFC and face matching, sharing and verifying passport data through QR codes, recording parental consent, and validating MRZ data.

I implemented the mobile UI, navigation, state management, generated data models, native-device integrations, API communication, local persistence, and Android/iOS configuration. The project uses a reusable bilingual Thai/English design system and handles loading, success, validation, retry, and failure states throughout long multi-step workflows.

INTERVIEW SUMMARY
I developed this project independently as a functional prototype for a Ministry of Foreign Affairs of Thailand bidding demonstration, covering everything from the application structure and reusable UI components to API and native-device integrations. The main technical challenge was coordinating a long identity-verification journey in which data from document scans, NFC chips, biometric captures, user forms, uploaded files, and backend responses had to remain consistent across many screens. I used Riverpod to manage shared and asynchronous state, GoRouter to model the multi-step journeys, and generated immutable models to keep API data predictable. I also built clear success, retry, and error states around hardware-dependent steps such as camera, MRZ, NFC, QR, and facial capture.
